# 对话迁移打包

## 用途与背景

用户使用多台电脑（工作 / 家用）上的 WorkBuddy，各机器的本地记忆文件不互通，迁移包是约定的唯一同步手段。用户的硬性要求：**保留所有原文内容，字节级保真——emoji 不省略（影响语气）、markdown 链接保持 `[文字](url)` 格式确保可点击跳转、代码块/加粗/列表全留。摘要不能替代原文。**

## 两个核心原则

1. **人看的部分必须字节级保真**：`对话全文.md`（给人看的）要 100% 原样——emoji 不省略、链接保持可点格式、所有 markdown 标记原样保留。给 AI 看的部分（`memory/MEMORY.md`）是摘要，但关键事实须精确双写（见下文）。
2. **实时累积优于事后重建**：对话进行中就把原始流追加到文件，打包时直接拷贝，不手工重建、不归一化格式。

## 触发时机

- **默认激活（最高优先级）**：**本用户的每一场会话都视为潜在迁移对象，实时累积默认开启。** 无需用户说出任何关键词——会话一开始就先**查重定名**（见「命名规则」：当天本机已有包则用 `迁移包_<当天日期>_<序号或主题>/`），再建包目录、`memory/` 子目录与 `实时对话流.md`，之后逐轮静默追加。
  - 理由：用户习惯打开窗口直接开聊，不会记得先声明"要实时累积"。**要求用户记得说，等于默认没有。**
  - 静默执行，不打断对话、不请求确认、不在回复里反复提醒。用户随时说"打包"即得字节级全稿。
- 用户说出"打包对话""迁移对话""迁移到另一台电脑/机器""拷回家/拷到公司接着聊""导出这次聊天"等，立即执行完整打包流程，无需追问细节。
- 用户表达"以后要迁移""记着拷到另一台""回家接着聊"等**迁移意图**时——**此时应当已经在累积了**，只需确认 `实时对话流.md` 存在且完整，无需补建。
- **中途补救（重要，务必先检查）**：本 skill 只在被加载时生效，而它往往**是用户说"打包"时才被加载**——此时会话已经跑了很多轮，累积机制根本没机会启动。所以：
  - **用户一说"打包"，第一件事是检查当前工作区的 `迁移包_*/实时对话流.md` 是否存在。**
  - 若不存在 → 说明本条规则在本场会话失效（因为 skill 没在会话开始时加载）。**先按下文「⭐ 最优解：直接抽取系统会话库原始记录」从 `~/.workbuddy/projects/<工作区转义>/*.jsonl` 抽取字节级全文**（2026-09-30 实测：33 轮会话一次抽出 48,745 字节，格式零丢失，不必事后重建）；只有当会话库确实不可用（找不到目录/文件为空）时，才降级到事后重建，并明确告知用户"本轮包为事后重建版，非字节级"。
  - 若会话**仍在进行中**（用户只是中途提到要迁移），则**从当前轮起立即开始真实累积**，历史轮次事后重建——不要因为"开场没建"就整场放弃累积。
  - **模式切换补救（2026-09-17 实测补充）**：若会话开始时处于**无写入权限的模式**（Ask / Plan），或 skill 因任何原因未在开场加载，则在**获得写入能力的第一个回合**立即补建包目录与 `实时对话流.md`（**先按「命名规则」查重定名**），从当前轮起真实累积；已发生的轮次按事后重建补齐，并在流文件顶部注明「第 N–M 轮为事后补建」。**不要等用户说"打包"才补**——越晚补，能字节级保真的轮次越少。
  - **为什么必须写这条**：实测已知，本 skill 的"默认激活"依赖会话开始时被加载，而实际加载时机经常滞后。仅靠"进场即建包"这句话不足以兜住，必须靠"打包时先检查"这一步兜底。
  - **打包后继续累积（2026-09-30 补，易漏）**：用户说"打包"之后，会话通常**还在继续**。要在打包收尾时于包内补建 `迁移包_<日期>/实时对话流.md`，顶部注明「第 1–N 轮见 `对话全文_<日期>.md`（系统抽取，字节级）」，**并从下一轮起逐轮追加**。否则：① 后续轮次又得重新抽取；② 用户把包拷到另一台机器后接着聊，缺的正好是这一段，两边内容就分叉了。
- 若用户明确说"只要摘要、不要原文"，则跳过对话全文，只生成 memory/ 与迁移说明.md。
- **例外（不启动累积）**：一次性的极小查询（如"今天几号""帮我看下这个字"）或无实质内容的一句问答，可不建包；用户明确说"这次不用打包"时也不建包。

## 实时累积模式（默认开启，不需要用户声明）

**会话开始即激活**（见"触发时机"）。**先按「命名规则」查一次重**（同日已有包就不能再用基础名），再在工作区创建包目录及 `memory/` 子目录，并新建 `实时对话流.md`：

- 当天本机**第一个**包 → `迁移包_<当天日期>/`
- 当天**第 2 个及以后** → 先用序号占位 `迁移包_<当天日期>_2/`、`_3/`…（此刻还不知道聊什么，等打包时再换成主题词）

**不要把新会话续写进当天更早的那个包里**——那是另一场对话，混在一起两边都看不清、事后也没法拆。只有当用户明确说"就接着上次那个包继续写"时才续写。
（旧版本曾规定"同一天第二场会话追加续写、不覆盖"，**2026-09-30 起作废**：用户当天可能有好几场主题完全不同的对话，合并只会毁掉两边的可读性。）

**此后每一个对话轮次结束后**，将本轮内容追加到 `实时对话流.md`：

- **用户原话**：从 `user_query` 提取，**原样保留所有 emoji、换行、格式**，不加概括、不省略语气符号。
- **助手回复**：**原样保留所有 markdown 标记**（`**加粗**`、有序/无序列表、`>` 引用、标题层级）、**所有 emoji**、**内联链接 `[文字](url)`**（保持可点击格式，不得改成纯文字）、代码块。不得"整理""归一化"或"美化"格式。
- 每轮用 `## 第 N 轮` 分隔，轮次从 1 开始递增。
- 工具调用 / 文件操作：用一行 `[工具: 生成图片 勇气清单.png]` 之类括号注记，不展开原始参数。
- 会话中展示过的附件（图片 / HTML / SVG）：在对应轮次标注文件名，并在打包时作为独立文件拷入 `迁移包_<日期>/`。
- Visualizer widget：在对应轮次标注"（展示图表：<标题>）"，并将生成的图片/文件作为附件拷入，不重画 SVG。

这样当用户最终说"打包"时，`实时对话流.md` 即为**字节级精确**的对话全文，人看和原屏一致。

## 事后重建模式（降级兜底）

仅当工作区确实没有 `实时对话流.md` 就直接说"打包"时，才走事后重建：从会话摘要重建逐字稿。此时**必须向用户声明**这是"信息完整非字节级"版本（emoji/格式可能归一、链接可能丢失、Visualizer 图表需重画），并建议未来用实时模式或 WorkBuddy 系统原始导出补。已知简化：

- **保留**：用户提问 100% 逐字；助手回复的论点、数据、结论、来源链接完整复现。
- **简化**：Markdown 排版细节、emoji、超链接完整 URL、工具原始参数，会被摘要归一化或省略。
- **重建**：Visualizer widget 的 SVG 原始代码在摘要里被省略，需近似重画——信息一致，外观不完全相同。

## ⭐ 最优解：直接抽取系统会话库原始记录（2026-09-29 实测打通）

**结论：`实时对话流.md` 不存在时，不必走事后重建。** WorkBuddy 把每一场会话的完整原始记录落在本机：

```
~/.workbuddy/projects/<工作区路径转义>/<会话ID>.jsonl
```

**路径转义规则**（实测）：`C:\Users\sonny\WorkBuddy\2026-09-29-13-18-03`
→ `c-Users-sonny-WorkBuddy-2026-09-29-13-18-03`
即：**去掉盘符冒号 → 盘符转小写 → 反斜杠换连字符**。
（⚠️ 坑：把 `:` 直接换成 `-` 会得到 `C--Users-...`，目录名对不上。必须先删冒号再小写。）

**现成脚本**：`scripts/extract_session.py`（本 skill 自带，Python 3 无第三方依赖）

```bash
# 在工作区根目录执行，自动定位当前会话
python ~/.workbuddy/skills/chat-migration-pack/scripts/extract_session.py \
       "" "迁移包_2026-09-29/对话全文_2026-09-29.md"
```

**JSONL 结构**：每行一个事件，`type` ∈ `message` / `function_call` / `function_call_result` / `reasoning` / `file-history-snapshot` / `session-meta` / `ai-title`。
正文在 `message.content[].text`（`input_text` 或 `output_text`），时间戳为毫秒。

**⚠️ 关键处理**：用户消息里混着系统注入块（`<system-reminder>`、身份文件、`<memory>`），**必须只取 `<user_query>...</user_query>` 的内容**，否则全文会被噪音灌满。

**产出质量**：**真字节级**（emoji / markdown / 链接原样），且带精确时间戳 —— **优于事后重建，接近实时流**。

**优先级**：① 实时对话流 → ② **系统会话库抽取（本节，字节级）** → ③ 事后重建（最差）。

> 实测样本：① 2026-09-29 本场 25 轮会话抽出 31,128 字 / 68.7 KB，格式零丢失。② 2026-09-30 本场 33 轮会话（Adobe×Clash 工具开发）抽出 48,745 字节 / 21 个包内文件，emoji、`**加粗**`、可点链接、表格全保留；**注意 `widget_code` 与工具参数不在 message 文本里，抽取前若会话展示过 Visualizer 图示，需当场另存 SVG**。

## ⚠️ 命名规则：一天多场对话必须加后缀（2026-09-30 实测踩坑）

**根本原则：一个对话 = 一个包。** 一天里可能有好几场主题完全不同的对话需要打包；如果都叫 `迁移包_<日期>`，轻则互相覆盖，重则用户拷 U 盘 / 同步网盘时分不清谁是谁。

### 命名格式

```
迁移包_YYYY-MM-DD                ← 当天第一个包（无冲突时才用）
迁移包_YYYY-MM-DD_<主题>         ← 当天第 2、3…个包
对话全文_YYYY-MM-DD_<主题>.md     ← 内层全文，后缀必须与包目录一致
```

### 建包 / 打包前必做：查重（含脚本）

**查重范围是全机、不只是当前工作区**——同一天的多场对话通常落在不同工作区目录下。

```bash
# 推荐：一行拿到可用包名（脚本已含查重 + 顺延逻辑）
python ~/.workbuddy/skills/chat-migration-pack/scripts/pick_package_dir.py

# 已知主题时直接指定（推荐，名字更好读）
python ~/.workbuddy/skills/chat-migration-pack/scripts/pick_package_dir.py 2026-09-30 模型选型
#   → 迁移包_2026-09-30_模型选型
#   → 若已被占用则自动变成 迁移包_2026-09-30_模型选型_2

# 只看当天已占用哪些包
python ~/.workbuddy/skills/chat-migration-pack/scripts/pick_package_dir.py --list

# 只想拿包名给 shell 用
PKG=$(python .../pick_package_dir.py --plain)
```

手写等价命令（脚本不可用时）：`find ~/WorkBuddy -maxdepth 2 -type d -name "迁移包_$(date +%F)*"`

判定：
- **当天本机没有同日期包** → 用基础名 `迁移包_<日期>`。
- **已有同日期包** → **必须加后缀**，绝不复用基础名。

### 后缀怎么取（优先级从高到低）

1. **主题词**（2–4 字，一眼看出聊了什么）：从会话 `ai-title`、用户首轮需求、或本场核心交付物提炼。
   - 先例：`_Adobe互斥`、`_模型选型`、`_jev`、`_图片质检`。
   - 已有包名再取同名主题时会自动顺延成 `_模型选型_2`，不会撞。
2. **序号占位**：会话刚开始、还不知道会不会打包 → 先用 `_2`、`_3`（= 当天第几个包）。
3. **打包时把序号换成主题词**（目录 + 内层全文 + 所有引用一起换）。实在提炼不出主题，保留序号也可以——**数字不好看，但绝不重名**。
4. **不要**用 `_p1` / `_p2` 这类事后看不懂的编号。

### 事后才发现重名：改名清单

| 要改的地方 | 怎么改 |
|---|---|
| 包目录名 | `迁移包_<日期>` → `迁移包_<日期>_<主题>` |
| 内层全文名 | `对话全文_<日期>.md` → `对话全文_<日期>_<主题>.md` |
| `迁移说明.md` | 顶部加「关于本包的名字」说明改名原因；结尾加「同一天还有哪些同名包」对照表；生成信息表补「**包名**」「命名说明」两行 |
| `实时对话流.md` | 顶部对全文文件的引用路径同步改 |
| `memory/<日期>.md` | 提到旧包名的行**追加**一条改名记录（日志只追加、不改写历史） |
| 包内 skill 副本 | 若该轮 skill 基线有更新，重新从基线拷一份进包 |

**唯一不动的地方**：`对话全文_<日期>_<主题>.md` **正文里**出现的旧包名——那是字节级保真的历史记录，改了就不叫保真了；在 `迁移说明.md` 里解释即可。

### ⚠️ 改名技术坑（别误判成文件被占用）

Git Bash / MSYS 的 `mv` 在**中文源名 → 中文目标名**时会报 `Permission denied`，即使 `icacls` 显示 Full Control、目录内容可写、同目录其它成员（`memory`/`skills`）改名正常。**这不是文件锁，别去查句柄**（Restart Manager / `Add-Type` / `cmd` 在用户机器上被安全网关拦截，纯属白折腾）。解法：插一个 ASCII 中转名，分两步走——

```bash
mv "中文旧名" tmp_rn     # 中文 → ASCII，必成功
mv tmp_rn "中文新名"     # ASCII → 中文，必成功
```

目录与文件同理。2026-09-30 实测：`附件` → `附件_t` **失败**；`附件` → `att_t` 成功，`att_t` → `附件` 成功；`迁移包_2026-09-30` → `迁移包_2026-09-30_Adobe互斥` 失败，走两步法一次通过。

## 输出结构（固定，不得更改）

在当前工作区根目录创建 `迁移包_YYYY-MM-DD/`（日期为当天）。**若当天本机已有迁移包，必须按上节加后缀** `迁移包_YYYY-MM-DD_<主题>/`，内层全文同步为 `对话全文_YYYY-MM-DD_<主题>.md`：

```
迁移包_YYYY-MM-DD[_主题]/
├── 对话全文_YYYY-MM-DD[_主题].md  ← 本次会话逐轮 Q&A 原文（实时流优先，字节级保真）
├── <附件>.png / .svg / .html    ← 会话中生成的插图或页面，独立可直接打开
├── memory/
│   ├── MEMORY.md                ← 与本会话相关的长期记忆摘录 + 给目标机器助手的指令
│   └── YYYY-MM-DD.md            ← 当日工作日志（如存在则复制）
├── skills/
│   └── chat-migration-pack/     ← 本 skill 本体（目标机可能未装）
└── 迁移说明.md                  ← 包结构说明 + 目标机器操作指引
```

## 执行步骤

0. **先定包名（查重）**：跑 `python ~/.workbuddy/skills/chat-migration-pack/scripts/pick_package_dir.py <日期> [主题]`，拿到不重名的包目录名与内层全文名。当天已有包 → 必加后缀，见「命名规则」一节。**不要跳过这一步直接建 `迁移包_<日期>`**。
1. 若 `实时对话流.md` 存在：将其内容作为 `对话全文_YYYY-MM-DD[_主题].md`（拷贝或改名），**字节级保真，不改动任何格式**。若不存在：按事后重建模式生成（并声明限制）。
   - **打包时机提醒**：用户说"打包"时若 `实时对话流.md` **缺少最后一轮**（当轮尚未追加），必须**先补写最后一轮再拷贝**，否则会丢最新内容。
2. 导出会话中生成的全部附件为独立文件：图片/SVG/HTML 保持可直接打开；SVG 须把 `var(--font-sans)` 等 CSS 变量替换为显式字体栈（如 `'Microsoft YaHei','PingFang SC',sans-serif`），并加白底圆角外框 rect。
   - **用户粘贴的截图**存在 `~/.workbuddy/clipboard-images/`，命名 `clipboard-<UTC时间戳>-<hash>.png`（**UTC 比北京时间少 8 小时**，如 `T05-21-04Z` = 本地 13:21）。按本场会话的时间范围筛出对应几张拷入 `附件/截图/`。
   - **⚠️ Visualizer 图示不在抽取的全文里**：`show_widget` 是工具调用，`widget_code`（SVG/HTML 源码）不会出现在 `message` 文本中，系统抽取拿不到。必须**另存为独立文件**：把 widget 源码写成 `.svg`（替换 CSS 变量为显式字体栈、加白底圆角外框），或按当时的设计重画。若当场没留源码，就按全文里的标题与描述重建近似版，并在迁移说明中注明"图示为重建近似版"。
3. 写 `memory/MEMORY.md`：从本机用户记忆（`~/.workbuddy/MEMORY.md`）与项目记忆中摘录和本会话主题相关的条目，开头附"给目标机器助手的指令"——阅读后将要点并入目标机用户记忆（`~/.workbuddy/MEMORY.md`），然后直接与用户继续对话，不要重复询问本文件已覆盖的信息。**关键事实（如人名、事件、数字、用户自我剖白）须精确，不得用猜测填充。**
4. 写 `迁移说明.md`：标题注明迁移方向（方向不明写"本机 → 另一台电脑"或询问用户）；包含目录结构图（逐项注释）+ 目标机器三步操作：① 打开 WorkBuddy 新对话；② 发送 `memory/MEMORY.md` 并说"读取这个文件并记住"；③ 发送 `对话全文_YYYY-MM-DD[_主题].md` 说"接着聊"（或开新话题）。若本次为事后重建非字节级，在说明里注明"非字节级"限制。
   - **包名带后缀时**，顶部加一段「关于本包的名字」说明为什么加后缀，结尾加「同一天还有哪些（同名）包」对照表（列出当天各包的位置与主题），生成信息表补「**包名**」「命名说明」两行。目的：用户过几天回头看，能立刻分清哪个是哪个。
5. 拷贝本 skill 目录到 `迁移包_日期/skills/chat-migration-pack/`（目标机可能未装）。
6. 调用 present_files 展示包内全部文件，用 3–5 句话向用户说明包内容与拷贝方法（U盘/网盘/文件传输均可，整体拷贝）。

## 多副本版本基线（重要）

本 skill 在本机存在**多处副本**，会各自漂移，必须明确唯一基线：

- **唯一基线**：`~/.workbuddy/skills/chat-migration-pack/SKILL.md`。任何修改只在这里做，其他位置都是只读副本。
- 已知副本（**2026-09-30 全机重扫结果**，此前的"桌面展示副本"已不存在）：
  | 副本位置 | 版本状态 |
  |---|---|
  | `Documents\GitHub\workbuddy-chat-migration\skills\chat-migration-pack\` | ✅ **2026-09-30 已同步至最新基线**（对外发布用，含 `scripts/` 两个脚本）。同步前的旧版（7918 B / 09-08）留存为同目录 `SKILL.md.bak`，该文件名已写入仓库 `.gitignore`，**不进公开仓库**——git 历史本身就是回滚手段 |
  | 当日其它迁移包内嵌 `迁移包_*/skills/chat-migration-pack/` | 视建包时间而定，通常落后基线 1 代以上 |
  | 历史迁移包内嵌（08-03 / 08-04 / 09-08 / 09-11 / 09-14 / 09-15 / 09-16 / 09-23 / 09-24 / 09-29 …） | 一律为各自建包时的旧版 |
  - 判定方法（一条命令出全表）：`find ~ -maxdepth 6 -path "*chat-migration-pack*" -name "SKILL.md" -printf "%TY-%Tm-%Td %10s  %p\n" | sort -k3`，再对基线跑 `md5sum` 比对。
- **修改基线后**：主动告知用户各副本的落后状态并询问是否同步；同步原则是新覆盖旧，且旧版先备份为 `SKILL.md.bak`。
  - **同步到 GitHub 仓库的完整流程（2026-09-30 实测）**：① `cp` 旧 `SKILL.md` → `SKILL.md.bak`；② 从**基线**拷 `SKILL.md` 与整个 `scripts/`；③ `md5sum` 双向比对确认一致；④ 同步更新仓库 `README.md`（新增的能力要进特性表与使用说明，否则仓库门面落后于 skill）；⑤ `git add` → `commit` → `push`（本机需 Clash 代理 `http://127.0.0.1:7897`，代理配置已在仓库级 `http.proxy`，直连也可但走代理更稳）。
  - **⛔ 顺序陷阱**：脚本/skill 内容里若包含"某副本是否最新"这类**状态描述**，改完基线要把该状态一起改对，**然后才拷贝到仓库**，否则仓库里躺着一份自述"落后"的最新版，下一轮又会误判为待同步。
- **实测坑（2026-09-16）**：桌面副本与 GitHub 仓库曾停留在 8-5 旧版（缺少"默认激活""中途补救"等关键条款），2026-09-08 / 09-14 迁移包内嵌的同样是旧版。**把旧迁移包拷到另一台机器，会用旧 skill 反向覆盖目标机的新版**。
  - 因此打包时拷 skill，**必须从基线目录复制，绝不能从手头的旧迁移包里复制**。
  - **2026-09-30 再次应验**：当天 09:01 与 11:29 两个包内嵌的是旧版，而 13:21 建的这个包当时已换成新版。同日多包时，**只有最新那个包的 skill 是新的**。
- 用户问"这个 skill 是最新版吗"时 → 用 `md5sum` + `stat` 批量比对上述各副本，输出对比表格，标出落后代数与缺失条款。

## 使用边界与已知限制

- **实时模式 = 字节级精确**：emoji、链接、格式全保留，人看和原屏一致。**默认开启**，无需用户声明。
- **事后模式 = 信息完整非字节级**：见上"事后重建模式"。仅作降级兜底，正常情况下不应出现。
- **历史轮次补字节级**：本次对话开始前已发生的历史内容，agent 视角在对话结束后只有摘要，无法从摘要恢复字节级。要绝对字节级，需从 WorkBuddy 系统原始对话导出获取——这不是本 skill 手工重建能解决的。
- **累积是静默的**：每轮追加 `实时对话流.md` 时不要向用户播报、不要请求确认。用户感觉不到它的存在，只在说"打包"时收获成果。
- **跨工作区注意**：包建在**当前会话的工作区根目录**。若用户同日跨工作区聊天，各工作区各自建包、**各自加后缀区分**（见「命名规则」），**不需要合并**——一个对话一个包，合并反而毁掉可读性。
- **一天多场对话**：这是常态，不是例外。每场会话开场就查一次重；打包前再查一次（中途可能有别的会话也建了包）。查重是**全机**范围，只看当前工作区会漏。

## 约定

- 文件名一律用中文，日期格式 YYYY-MM-DD。
- **包目录名的唯一性优先于简洁**：**一天多场对话 → 一个对话一个包，第 2 个起必加后缀**；宁可名字长，不可两包同名。查重用 `scripts/pick_package_dir.py`。
- **后缀在包目录与内层全文上必须一致**（`迁移包_X_主题/` 配 `对话全文_X_主题.md`），否则用户按说明找文件会找不到。
- **skill 本身也按机器隔离**：迁移对话时，把本 skill 目录一并拷贝进迁移包（放在 `迁移包_日期/skills/chat-migration-pack/`），并在迁移说明里给出"目标机安装 skill"的步骤。
- 对话全文是留档原件（给人看，须字节级保真）；memory/MEMORY.md 是记忆吸收摘要（给 AI 看）；两者职责不同，不得互相替代。
- 打包完成后，把"本次已打包"的事实追加到本机当日工作日志（`.workbuddy/memory/YYYY-MM-DD.md`）。
